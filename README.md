# Image Converter

A single, self-contained HTML tool that converts images between **PNG**, **JPG**, and **WebP** — entirely in your browser. No server, no build step, no uploads. Your images never leave your device.

Open `index.html` by double-clicking it (works from `file://` in Firefox and Chrome), or host it anywhere static as an installable PWA.

## Features

- **Drag-and-drop** or click to browse (`<input type="file" multiple>`).
- **Batch mode** — convert many images at once.
- Per-image **thumbnail, original filename, format, and size**.
- **Global output format** (PNG / JPG / WebP) with an optional **per-file override**.
- **Quality slider** (0–100) for JPG/WebP; hidden for PNG (lossless).
- **PNG → JPG transparency flattening** onto a color you pick (default white).
- **Image resizing** — Max dimension (px), percentage scale (%), or custom dimensions (W × H) with aspect ratio lock.
- **Before/after size, dimensions, and percent savings** per file, plus a batch summary.
- **Per-file download** links and **Download all as ZIP** (via JSZip).
- Correct **extension swapping** on output filenames (`photo.png` → `photo.jpg`).
- Light, Material-ish, responsive UI.

## How it works

Conversion is done client-side: each image is drawn to an offscreen `<canvas>` with high-quality anti-aliasing and exported with `canvas.toBlob(mime, quality)`. Files are read from local `File` objects via `URL.createObjectURL` — **there is no network fetch of image data at any point.**

## Dependencies

The only third-party code is **[JSZip](https://stuk.github.io/jszip/)** v3.10.1, used solely for the "Download all as ZIP" button. It is **vendored locally** at `vendor/jszip.min.js` (MIT/GPLv3 — see `vendor/JSZip-LICENSE.markdown`), so the app makes **zero network requests** and ZIP works offline and under `file://`.

The vendored file is byte-identical to the cdnjs build it replaced (verified against `sha512-XMVd28F1oH/O71fzwBnV7HucLxVwtxf26XV8P4wPk26EDxuGZ91N8bsOttmnomcCD3CS5ZMRL50H0GgOHvegtg==`). To update it: `npm pack jszip@<version>` and copy `package/dist/jszip.min.js` into `vendor/`.

## PWA / offline

When **served over http(s)**, the app is installable and works offline via `manifest.webmanifest` and `sw.js` (cache-first app shell). Under `file://`, browsers ignore the manifest and won't register a service worker — that's expected, and the converter still works fully.

Icons (camera theme) live in `icons/` and are generated by `icons/generate_icons.py` (run `python3 icons/generate_icons.py` to regenerate).

## Known limitations

- **EXIF orientation:** modern Firefox/Chrome auto-apply EXIF orientation when rendering `<img>`, so phone photos convert upright. Engines that don't auto-orient could draw a rotated JPG sideways. Manual EXIF rotation is deferred to v2.
- **HEIC/HEIF input** is out of scope for v1 (would require a WASM decoder such as `heic2any`).
- No cropping or advanced photo editing filter operations.

## Privacy & security

All processing is local to your browser. No account, no telemetry, no persistence between sessions, and no image data is ever transmitted. With JSZip vendored locally, the app makes **no network requests of any kind** — you can verify this with an open DevTools Network tab, or by running it with the machine offline.

Filenames are HTML-escaped before display, so a file with markup in its name (e.g. `foo" onerror="….png`) renders as text rather than injecting attributes into the page.
